## In my own words
<!-- Explain it as if to someone who doesn't code. -->
`T(n) = 2n² + O(n)` describes the total work of an algorithm in two parts:

- **2n²** is the main part, which we count exactly (in my example, the nested loops).
- **+ O(n)** is extra work we don't count exactly: an "anonymous" amount that we only know stays **under a linear ceiling**.

We write it this way because, next to the main part, the extra barely matters, and its exact count depends on how you count steps anyway. `O(n)` says what's important without false precision.

## Key ideas
- O inside an expression stands for **some** function we don't name, with a ceiling: `+ O(n)` = "plus something that grows at most linearly".
- The O part is **added**, not multiplied.
- The anonymous part can come from anything (a loop, `slice`, `includes`, a constant like `+ 7`), as long as it stays under the ceiling.
  - `+ 7` → fits under O(n) (true).
  - `+ 1,000,000 · n` → still linear, fits (true). Size doesn't matter, growth does.
  - `+ n² / 2` → quadratic (×4 when n doubles), breaks the linear ceiling (false).
- Why `n² + O(n)` is quadratic overall: the linear part keeps growing, but its **share** of the total shrinks toward 0 (≈0.2% at n = 1,000; ≈0.0001% at n = 1,000,000).
- Hidden loops: `slice`, `includes`, `shift` and spread are O(n), even when they run once outside a loop.

## Example (JavaScript)
```js
function f(arr) {
  for (const a of arr) for (const b of arr) { count(a, b); count(b, a); } // 2n² (exact)
  for (const x of arr) log(x);                                           // extra, ~3n + 7
}

// T(n) = 2n² + O(n)
// At n = 1,000: 2n² = 2,000,000 and the extra is ~3,000 → about 0.15% of the total.
```

## Exercises I solved

1. `T(n) = 3n² + O(n)` when the extra is actually `5n + 100`: **true**, because 5n + 100 is still linear, so it stays under a linear ceiling.
2. `g(arr)`: one loop over `arr`, then `arr.slice()` after the loop. Is `T(n) = n + O(1)`? **False.** `slice` runs once, but it copies every element (a hidden loop), so it's O(n): `T(n) = n + O(n)`. *(I needed help with the reasoning.)*
3. `h(arr)`: nested loops, then `arr.includes(0)`: `T(n) = n² + O(n)`, because `includes` grows with n.

## Mistakes I made
<!-- What did you get wrong during the session, and what's the correct idea? -->
1. I said `+ O(n)` means "a separate loop". Correct: it's any anonymous extra work that stays under a linear ceiling. It may come from a loop, but not necessarily.
2. I said the extra work "can be any operation". Correct: only work that grows at most linearly fits under O(n).
3. I said `2n² + O(n)` is still true if the extra is `n² / 2`, and that quadratic "doubles". Correct: n² / 2 goes ×4 when n doubles (quadratic), so it breaks the linear ceiling and the statement is false.
4. I said the extra part is "a number to multiply our work by". Correct: it's **added** (`+`).
5. I said the expression is true "because the difference is not huge". Correct: it's true because of the ceiling, not because the amount is small (1,000,000 · n also fits).
6. I said `arr.slice()` outside the loop "never runs" and "copies 3 elements no matter n". Correct: it runs once per call and copies all n elements, so it's O(n).
7. I said "the O(n) part gets smaller" as n grows. Correct: it keeps growing; its **share** of the total gets smaller.
